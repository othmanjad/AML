# Implemented features and known gaps

## Implemented (end-to-end: database → API → UI → tests)
- **Dynamic customer fields** — draft/publish/approve/version/deactivate, typed EAV values (effective-dated, history, sensitive masking, AES-GCM encryption + HMAC search), options, groups, role layouts, where-used/dependency blocking, server-side validation, searchable-field filters with index.
- **Customers & CDD** — server-side list/search/filters/column preferences, sensitive search by POST, 14-tab profile, financial profiles, documents, identifications, ownership (multi-level, configurable UBO threshold, control by other means, cycle detection), acceptance policy decisions, SDD/CDD/EDD assignment + EDD tasks, do-not-onboard list, exit workflow with neutral codes, KYC-expiry tasks.
- **Risk** — versioned methodologies (weighted average, capped sum, max-factor, category matrix), mappings, thresholds, mandatory overrides (PEP, sanctions), category floors, missing/stale data policies, validation (gaps/overlaps/weights/score range), four-eyes approval, effective dating, simulation, immutable assessments with config snapshot, event-triggered/idempotent reassessment, manual overrides with approval, review scheduling/escalation.
- **Transactions** — idempotent batch ingestion with payload hashing, conflict quarantine, out-of-order status handling, reversals/refunds (incl. before original), clearing-wallet party resolution, FX with versioned rates (never defaulted to 1), DQ issues, dead-letter + replay, retry with backoff, reconciliation vs control totals, outbox, incremental daily aggregates.
- **Rules & alerts** — JSON DSL with allow-listed fields/operators/aggregates, limits on depth/size, rolling/calendar windows in Asia/Amman, maker-checker lifecycle, simulation/backtest (dry-run or tagged alerts), tuning ATL/BTL, execution log, configurable dedup keys, immutable match evidence, alert workflow with SLA (working-day calendar), closure policies (four-eyes, checklist), QA sampling/reopen.
- **Cases & reporting** — cases with links, immutable notes, tasks, evidence uploads (type/size/magic bytes/malware check, stored outside web root), transitions/approvals; STR from case only, narrative/indicator requirements, goAML-style XML + XSD validation, MLRO approval, sandbox/manual submission, acknowledgements, amendments, deadline SLA; authority requests.
- **Screening & actions** — internal watchlist provider (Arabic/Latin normalisation, transliteration-tolerant matching), list versioning, delta rescreening, allow-list with invalidation, PF category, encrypted provider responses, compliance actions with idempotency/approval/retry/reconciliation via a mock core adapter, freeze notifications.
- **Real-time** — decision API with latency budget and per-segment fail-open/fail-closed policies, name/free-text screening, real-time rules on pre-computed aggregates, hold queue with SLA escalation, linking to ingested transactions.
- **Governance & security** — entity resolution (identity token, contacts, device, IP, similar names) and permission-aware graph, effectiveness metrics, typology coverage, feed completeness, validation pack, retention dry-run/approval/execution with legal holds, jurisdiction settings with legal source and approval, JWT/OIDC auth, permission matrix, data scopes, multi-tenancy, tipping-off controls, masked logging, tamper-evident audit, exports (CSV/XLSX, async, audited, formula-safe).
- **UI** — React/TypeScript/Ant Design SPA in English and Arabic (RTL), every module connected to the real API, permission-aware navigation, loading/empty/error/forbidden states with correlation IDs, confirmation for high-impact actions.

## Known gaps / not production-ready
| Area | Gap | Notes / next step |
|---|---|---|
| Core banking / wallet integration | Only `MockCoreSystemAdapter` exists (also in Production). | Implement a real `ICoreSystemAdapter` (freeze/release/hold/suspend + state lookup) and certify it; until then keep automatic freeze policies disabled in production. |
| FIU integration | goAML XML uses a structural baseline XSD; production channel is manual export + evidence. | Obtain the national FIU schema/version and API (if any). |
| Screening provider | Internal list matcher only; no commercial provider adapter; lists are fictitious test lists. | Add provider adapter (e.g. via `IScreeningProvider`) and official list feeds. |
| Malware scanning | `SignatureMalwareScanner` detects EICAR only. | Integrate an AV engine. |
| Identity | Dev token issuer for local use; OIDC supported by configuration but not tested against a real IdP. | Configure and test with the bank's IdP; MFA via IdP. |
| Jurisdiction values | All legal values seeded as *To be confirmed by compliance*; sample rules/thresholds flagged `IsSample` and disabled. | Compliance review and approval. |
| Non-functional | No peak-load, 24 h soak or DR fail-over test (TC-NFR-004/006 Blocked); single-host latency profile only. | Performance/DR testing on staging infrastructure. |
| Model governance | No ML/statistical models (AML-TC-0270 N/A). | Future extension. |
| UI | Role-permission matrix is read-only in the UI; no UI for device signals entry, entity graph visualisation, typology mapping, rule tuning, legal holds, provider-outage simulation, feed completeness/validation pack, EDD level re-assignment and exit approval (all available via API). Some dropdown lists (exit reason codes, action types, QA error categories, mapping/screening categories) are static in the UI. Single 1.6 MB JS bundle (no code splitting). | Incremental UI work. |
| Exports | Large exports are streamed by a background job but were tested with small volumes only. | Volume test (200k+ rows). |
| Arabic matching | Rule-based normalisation + Jaro-Winkler/skeleton transliteration; precision/recall measured on a small labelled set (20 pairs). | Grow the labelled regression set with compliance-approved examples; tune thresholds. |
